# Gemini-TTS sample library contract

All endpoints below are platform-admin endpoints under
`/api/v1/superuser/gemini-tts/sample-packs`. They accept either an interactive
super-admin `Authorization: Bearer ...` session or the server-to-server
`X-Platform-Admin-Key`. They never call Google while reading.

Pack settings are immutable: `model_id`, resolved `catalog_revision`,
`location`, `language`, `style_text`, and `sample_text`. `voice_id` is the
canonical Google voice ID from that model/revision catalog.

## 1. Generate all voices

`POST /sample-packs`

Request:

```json
{
  "model_id": "gemini-3.1-flash-tts-preview",
  "voice_id": "Kore",
  "catalog_revision": "<optional-current-revision>",
  "location": "global",
  "language": "en-US",
  "style_text": "warm and conversational",
  "sample_text": "Hello, this is a voice sample."
}
```

Returns `202` with the pack and exactly one queued asset when `voice_id` is
supplied. Omit `voice_id` to preserve the existing Generate all voices action;
that form queues all 30 catalog voices. Repeating the same request is
idempotent and does not requeue completed work. Creating the same pack later
without `voice_id` adds and queues only catalog voices that are still missing.

## 2. Generate one voice

`POST /sample-packs/{pack_id}/voices/{voice_id}/generate`

Request for a voice with no current sample:

```json
{"regenerate": false}
```

Returns `202` with the pack. Exactly one asset job is queued. Unknown voices,
or voices outside the pack's pinned model/revision, return `422`. A voice that
is already `queued` or `running` returns `409` with that state. A failed asset
must use the failed-only retry endpoint.

## 3. Regenerate one completed voice

Use the same endpoint with:

```json
{"regenerate": true}
```

Without this explicit confirmation, a completed voice returns `409` explaining
that a new Google TTS request for one voice will be sent and may incur usage.
Successful regeneration creates a new immutable version and makes it current;
the previous version remains available in the pack response.

## 4. Read current and prior versions

`GET /sample-packs/{pack_id}` (or `GET /sample-packs`)

The `assets` array contains all immutable versions. Each asset includes
`version` and `is_current`; clients should play the completed asset where
`is_current` is true. `sample_url` is signed for one hour. Prior versions can
be inspected or played with:

`GET /sample-packs/{pack_id}/assets/{asset_id}/playback-url`

The model-slot catalog also returns only the current completed sample for each
voice by default.

## 5. Recover failed voices only

`POST /sample-packs/{pack_id}/retry` accepts no body and returns `202` with the
existing pack response. It creates exactly one new immutable version for each
canonical voice that has failed history but no current completed sample and no
queued/running version. Historical failures are retained. Playable voices are
skipped even when they have older failed versions. A fully playable pack is a
successful no-op, with zero selected/enqueued jobs.

For a controlled platform-admin diagnostic, append `?limit=2` to cap the number
of selected voices using the exact same bulk scheduling path. Omit the query
parameter for one recovery pass over all eligible failed voices.

The response adds optional `retry_summary` without an envelope change:

```typescript
type GeminiTtsRetrySummary = {
  operation_id: string;
  eligible_voices: number;
  skipped_playable_voices: number;
  skipped_active_voices: number;
  selected_voices: number;
  enqueued_jobs: number;
  enqueue_conflicts: number;
  enqueue_failures: number;
  asset_ids: number[];
  job_ids: string[];
};
```

The pack response also adds `total_voices`, `playable_voices`, `eligible_voices`,
and `active_voices`. Existing `total_assets`, `completed_assets`, and
`failed_assets` remain version totals. Pack status tracks required catalog
voices: completed when all are playable, running/queued while missing voices
have active work, partial when some are playable, otherwise failed. Historical
failed versions do not prevent completion. Regeneration of an already playable
voice keeps its current audio available.

A scheduling conflict or failure returns `503` with
`detail: {message: string, retry_summary: GeminiTtsRetrySummary}`. Other jobs in
that operation may have been accepted: poll the pack before taking action.
Failed enqueue reservations become failed versions if still unclaimed, so they
cannot remain queued without a runnable job. A late job cannot claim them.
An already claimed job retains worker ownership. No enqueue/provider retries
are automatic. New versions use new ARQ IDs, independent of retained results.

`GEMINI_TTS_SAMPLE_CONCURRENCY` controls Redis-backed provider slots across all
API/ARQ processes (default `1`, valid `1..10`; use the same value for all
workers). A job that finds every slot busy does **not** wait inside its worker
slot: it leaves the asset `queued` and reschedules itself a few seconds later
(ARQ `Retry`), so a long batch cannot occupy the worker and delay unrelated
jobs. Waiting never sends Google requests; the 120-second provider deadline
begins only after a slot is acquired. Every sample permits exactly one outbound
request. Operation IDs persist in asset generation metadata and correlate
selection, enqueue, worker claim and final outcomes. No text, audio,
credentials or signed URLs are logged.

## Abandoned work: leases and recovery

A worker claims an asset (`queued` → `running`) with a random claim token and a
lease (180 s) that it renews while it works. Only the holder of the token may
finalize the asset. A cron sweep (`recover_stranded_gemini_tts_samples`, every
minute, safe to run on several workers at once) then repairs two failure cases:

- **Worker died or stalled** (`running` with an expired lease): the asset becomes
  `failed` with `error_message` beginning `worker_lost:` and its token is
  cleared, so the old worker cannot finalize it later. It is deliberately **not**
  re-run automatically, because the provider may already have been called and
  billed; use the failed-only retry, which creates a new version. A healthy
  (renewed) lease is never touched.
- **Queue job lost** (`queued` for over two minutes with no live ARQ job, for
  example after a Redis flush): the asset is re-enqueued under a new job ID
  (`...-e{epoch}`). No provider request has happened, so this is safe. Only one
  sweeper wins the epoch bump, so concurrent sweeps never double-enqueue.

Recovery never changes the current playable version or earlier history. The
additive migration `a9c3e5b7d1f2_add_gemini_tts_sample_leases` adds the claim
token, lease, queue timestamp and enqueue epoch columns; a job still running
under the previous release gets a ten-minute lease so it is not reaped mid-run.
Deploy the API and the workers together, because the sweep and the claim
protocol must agree.

## Audio format and location

The Vertex Gemini-TTS adapter checks the audio metadata Google returns with each
chunk. It must describe raw 16-bit PCM, one channel, at the model's native rate
(for example `audio/L16;codec=pcm;rate=24000`); anything else (a WAV container,
another rate, stereo) fails the sample with a clear error rather than being
stored or played as 24 kHz mono. When no metadata is sent the catalogue's
per-model format applies. Sample generation always uses the platform API key, so
it follows the same location rule as an API-key TTS slot: only `global` can be
requested (a key resolves any other location from its account), and a pack for a
regional location is rejected with the slot validator's message.

The AVSIQ consumer can keep its existing bodyless retry call. Poll the pack,
play only completed `is_current: true` assets, and use voice-level eligibility
(or derive it from version history) to control the retry button. Do not use
`failed_assets` to label a fully playable pack as broken or offer recovery.
